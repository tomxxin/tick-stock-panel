# 全市场竞价扫描设计

日期：2026-11-20。状态：待所有者审阅。本文只定义设计，不包含实现。

已批准范围：只使用扶摇公开文档中的 `GET /api/a-share/auction/snapshot`。交易日上海时间 09:26 自动采集，默认开启，界面可关。默认筛选为竞价涨跌幅至少 5 个百分点且竞价量比至少 10，两项都可改，改筛选不重新请求。支持手动采集。保存当日原始完整快照。不把盘中行情快照或短线风向标名单当作竞价扫描。不生成交易建议，不发单。不承诺 2 秒扫完。不能按日期回补启用前的 09:25。

基线代码是维表修复 `71ebdb705c9706c3d7dd36516657103d9a09c1e6`。实现时另开分支，不改该提交，不并入 PR #1。

## 已核实的接口形状

文档：<https://fuyao.aicubes.cn/docs/api-reference/auction/>

`GET /api/a-share/auction/snapshot`

| 参数 | 规则 |
| --- | --- |
| `thscodes` | 必填。英文逗号分隔。单次按分隔后的原始 token 计数，去重前最多 100 个。 |
| `stage` | 只发送 `final`。 |

响应 `data` 的已文档化字段：`timestamp`（毫秒，接口组装时间，不是竞价成交时刻）、`auction_phase`、`data_status`、`total`、`item`。

`item` 已文档化字段：`thscode`、`ticker`、`name`、`auction_price`、`auction_pct`、`auction_volume`、`auction_amount`、`auction_unmatched`、`auction_turnover_pct`、`auction_yesterday_ratio_pct`、`auction_volume_ratio`、`pre_close_price`、`open_price`、`last_price`、`float_market_cap`。

单位，只采用文档和现有风向标卡片已经用过的口径：

- `auction_pct` 是百分数原值。文档示例 `0.35` 对应约 0.35%。现有卡片用 `auction_pct >= 5` 表示高开至少 5%，展示时 `fmtPct(auction_pct / 100)`。筛选比较前不再除 100。
- `auction_volume_ratio` 按接口原值比较。文档示例是 `1.12`。默认阈值 10 就是与 1.12 同一标尺上的 10，不做换算。
- `auction_volume` 的股/手单位文档没有定义。原样保存和展示，不换算。

文档没有日期参数，因此不能指定历史交易日。文档没有把 `timestamp` 定义成 09:25 撮合时刻。上游竞价时间只用于服务端判断新鲜度，响应里没有这个时刻。

`data_status` 文档示例是 `ready`，正文提到 `not_ready`。其他取值没有文档。`auction_phase` 文档示例是 `final`。其他取值没有文档。

鉴权沿用现有扶摇 `X-api-key`。`2001` 是未认证，`2003` 是无权调用。`4001` 或 HTTP 429 是限流。没有公开的固定 QPS，也没有“约 2 秒扫完全市场”的文档依据。风向标接口返回成功不能证明本接口已授权。

明确不调用：`/api/a-share/prices/snapshot`、`/api/a-share/auction/short-term-benchmark`、`/api/a-share/special-data/auction-stock-opportunities`。后两者继续只服务现有风向标和未接入的机会名单，不参与本扫描。

## 有效终态的严格门闩

一次采集要成为“当日有效 09:25 终态”，必须同时满足下面全部条件。任一不满足，都不得写入或替换有效档，也不得把结果标成有效终态。

1. 扶摇交易日历 `GET /api/a-share/calendar/trading-days` 本次调用成功，且上海时间的今天出现在返回日期里。调用失败、空列表、无法解析，都是日历不可用，不采集。今天不在一份成功返回的列表里，就是非交易日，不采集。不用星期几推断交易日。
2. 本次运行的开始时刻，按 `Asia/Shanghai`，落在当天 09:26:00 到 10:30:00（含两端）。自动调度和启动补跑只允许在这个窗口开始。窗口外的手动采集走“未核验”路径，不能升格为有效终态。
3. 每个批次都请求了 `stage=final`，且该批 `auction_phase` 恰好是 `final`，`data_status` 恰好是 `ready`。`not_ready`、缺字段或其他未文档化取值都拒绝。
4. 每个批次的 `timestamp` 能解析为毫秒，换到 `Asia/Shanghai` 后的日历日等于本次交易日。时区不用服务器本地时区。任一时间戳跨日，整次运行拒绝。
5. 覆盖完整，见下一节。
6. 写入使用临时文件加原子替换。替换前校验不通过则删除临时文件，原有效档保持不动。

窗口按运行开始时刻判断。09:29 开始、10:32 才结束的一次完整成功，仍可成为有效终态。10:31 才开始的运行，即使返回 `final` 和 `ready`，也只是未核验结果。原因是响应里没有独立字段证明数据就是 09:25 撮合值，`timestamp` 只是组装时间。

## 覆盖校验

股票池只读 `data/instruments/instruments.parquet`，在运行开始时冻结，中途不重读。

合格代码同时满足：`symbol` 匹配 `^[0-9]{6}\.(SH|SZ|BJ)$`；若存在 `exchange` 列，则必须与后缀一致。空代码、格式不符、后缀和市场列冲突的行计入 `rejected_codes`，不进入请求。合格代码按 `symbol` 去重，保持稳定排序。

维表缺失、读失败或合格代码为 0：状态 `universe_unavailable`，不写有效档。这避免把残缺维表扫成一份“完整”空结果。

每批最多 100 个已去重代码。批与批不相交。请求串行发出。批与批之间至少间隔 0.15 秒。单请求超时 20 秒。

一个返回行要计入覆盖，必须有 `thscode`，且该代码属于本批请求。同一批里同一代码出现多次：各次字段完全一致则保留一条；不一致则该批失败。响应里多出来的代码不计入覆盖，只计入 `unexpected_codes`。请求了但没有返回行的代码计入 `missing_codes`。

`total` 若存在且不等于 `item` 长度，该批失败。

有效终态要求：失败批次数为 0，`missing_codes` 为空，每个合格代码恰好有一条已接受的行。否则本次不是完整采集。不把缺失代码补成空行或 0。

数值字段缺失或类型无法转成数字时，该代码仍然算已覆盖，原始值按 `null` 保存。筛选时 `auction_pct` 或 `auction_volume_ratio` 为 `null` 的行不命中，也不当成 0。

## 失败、部分结果和存储

传输类失败（网络错误、超时、HTTP 503、业务码 `5001`、`5002`、`5003`）每批最多再试 2 次。第一次等待 1 秒，第二次等待 3 秒。不用紧循环重试。这类重试耗尽则该批失败，继续后续批次，以便报告列出已跑过的失败批。HTTP 429 或业务码 `4001` 也最多再试 2 次，等待时间同样是 1 秒和 3 秒；耗尽后停止后续批次，避免继续顶着限流请求。`2001` 和 `2003` 不重试，立即停止后续批次。

部分失败或未通过门闩时：

- 不替换当日有效档。
- 不把前一交易日的有效档显示成今天。
- 界面展示这次失败运行的状态、失败批次、缺失数量和错误码。
- 若当天已经有一份更早的有效档，列表仍只来自那一份，并保持其原采集时间。没有当天有效档时，列表为空，并说明今天没有有效终态。

存储：

| 路径 | 内容 |
| --- | --- |
| `data/auction_scan/final/date=YYYY-MM-DD.json` | 仅有效终态。同日新的有效终态才原子替换。 |
| `data/auction_scan/unverified/date=YYYY-MM-DD.json` | 窗口外手动采集的最后一次未核验结果。不参与有效列表。 |
| `data/auction_scan/last_run.json` | 最近一次运行的状态摘要，可以是失败或部分失败。不是股票列表的数据源。 |

有效档损坏或写到一半：读侧视为当天无有效档，不回退到昨天，不把半截临时文件当结果。临时文件后缀不得是会被行情扫描误读的 `.parquet`。

未核验结果即使 `auction_phase=final` 且 `data_status=ready`，标签也只能是“未核验采集”，并显示响应组装时间。它不进入有效扫描，不参与默认列表。

API Key 只留在现有服务端密钥存储。响应、异常正文和日志不包含 Key。日志可以有业务码、批次序号和失败数量。

## 调度、手动和并发

沿用 `daily_pipeline.start_scheduler` 的上海时区工作日起床：周一至周五 09:26。星期几只决定进程是否醒来，不决定是否交易日。醒来后先查日历，日历不通过就不发快照请求。周日等调休交易日没有这只闹钟；只有进程在窗口内启动时的补跑，或窗口内的手动采集，才会在日历确认后采集。应用整段窗口都没运行时，当天没有自动结果。

同一进程内一把锁。自动、启动补跑和手动都进同一函数。锁被占用时，后来的调用返回 `already_running`，不再发请求。

自动路径（09:26 定时和启动补跑）在当天有效档已存在时直接返回，不发第二次请求。启动补跑只在进程启动时刻落在 09:26:00 至 10:30:00、今天是交易日、自动开关开着、且当天还没有有效档时运行一次。10:31 及之后启动不补跑。

Mac 休眠或应用没开导致 10:30 前进程不存在：定时任务不会补执行。醒来已过 10:30 时不自动采集。这是桌面进程的限制，不是数据恢复。

手动采集在窗口内可以再次运行。只有新运行通过全部有效门闩，才替换当天有效档。窗口外手动采集只写未核验档。自动开关关闭时，定时和补跑不运行，手动仍可用。

`2003` 的界面文案是当前 Key 无权调用集合竞价快照，并给出前往现有数据源设置的链接。不发起购买、升级或改 Key。

## 筛选和界面

偏好新增三个字段，旧偏好文件缺字段时用默认值：

| 字段 | 默认 |
| --- | --- |
| `auction_scan_enabled` | `true` |
| `auction_scan_min_pct` | `5` |
| `auction_scan_min_volume_ratio` | `10` |

筛选在已保存的当日有效档上本地计算。改阈值不发扶摇请求。

新增接口，不改现有 `/api/abnormal/intraday`、`/overview` 和 `/api/market-recap/auction-benchmark`：

- `GET /api/abnormal/auction-scan`：今天的展示状态。列表只来自今天的有效档。可另带 `last_run` 和未核验摘要，字段名分开。
- `POST /api/abnormal/auction-scan/run`：手动采集。
- `GET /api/abnormal/auction-scan/settings` 与 `PUT`：读写上面三个偏好。

`GET` 可选 `date=YYYY-MM-DD` 只用于明确查看历史有效档。缺省是上海时间今天。历史响应必须带该日期；前端不得把非今天的结果放进“今日”区域。

扫描卡片单独呈现状态：未配置、无权、日历不可用、非交易日、等待窗口、采集中、今日有效、今日无有效终态、最近一次失败或部分失败、未核验。覆盖数字包括合格代码数、返回数、缺失数和失败批次数。失败不替换整页，不挡住风向标卡片，也不挡住盘中和偏移两个页签。现有“未配置 fuyao 时竞价页引导去设置”可以保留；扫描失败不能把已经显示的风向标清掉。

页面上的“约 2 秒、5547 只”文案删除，改为实际覆盖数字和采集时间。

## 测试

实现时用假扶摇客户端和假日历，不使用用户 Key，不访问生产接口。至少两份响应夹具：一份包含文档中的全部 item 字段；一份缺少 `auction_volume_ratio` 或 `auction_pct`，该行入原始档但不命中筛选。

必须覆盖：

- 09:25 前不发有效采集。
- 09:26 在交易日、日历成功、全批次 `ready`/`final`、时间戳日期为今天、覆盖完整：写入有效档。
- 响应时间戳换到上海时间后不是今天：整次拒绝，不写有效档。
- 10:30 之后的手动运行：只写未核验档，有效档不变，界面不称其为 09:25 有效终态。
- 周末，以及日历成功但今天不在列表中的假日：不发快照请求。
- 日历请求失败：不发快照请求，状态为日历不可用。
- `503`、`429`/`4001` 在重试耗尽后：有效档保持原样，运行状态为失败或部分失败。
- `not_ready`、空 `item`、一批失败、合格代码缺失：不标完整，不替换有效档。
- 上一份有效档损坏、写入中断：读到的仍是中断前的完整文件，或明确的当天无有效档，不能读到半截内容。
- 默认阈值 5 和 10；改阈值后命中集合变化，且扶摇客户端调用次数不增加。
- `2003` 不重试，响应和日志不含 Key。
- 当天已有有效档时，自动路径不再次请求；手动窗口内允许再跑。
- 并发的第二次调用得到 `already_running`。
- 前端状态映射：覆盖数字、非今天的数据不显示成今日、失败不使用昨日列表冒充今日。

桌面安装仍用并列的未签名构建，不改已经装好的签名包和已经部署的维表修复包。数据目录仍是 `~/Library/Application Support/TSP`。第一次运行实现版本前，先复制整个数据目录。本功能只新增 `data/auction_scan/`，不写 `instruments.parquet`。
